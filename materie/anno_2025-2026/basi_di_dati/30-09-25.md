# Basi di dati

>[!definition] 
>Base Dati
>> Collezione di dati usata per rappresentare informazione di interesse per un dato sistema informativo, gestita da un DataBase Management System (DBMS)

Basi di dati supportano **astrazioni sui dati:**
+ livello fisico
	+ livello più basso
	+ DBMS decide dove salvare la tabella residenti di Udine
+ livello logico/concettuale
	+ non vede mai i file ma vede un insieme di tabelle e relazioni
	+ si collocano i due modelli concettuale e relazionale
+ livello delle viste
	+ ritaglio del modello logico

>[!example]
>In un'università, le informazioni relative ai docenti possono essere utilizzate in vario modo e da diverse persone o uffici; per esempio, potremmo avere le seguenti situazioni (alcune delle quali sono state semplificate o adattate a fini di presentazione): 
>- l'ufficio del personale è di solito responsabile delle informazioni relative alla "carrie-ra" (per esempio, alla distinzione fra ricercatore, professore associato e professore ordinario e all'anzianità); 
>- le direzioni dei dipartimenti (sulla base delle delibere dei consigli dei dipartimenti stessi) mantengono le informazioni sugli incarichi di insegnamento dei docenti; 
>- l'ufficio Web di Ateneo, interessato a pubblicare le informazioni sui corsi e i relativi docenti, utilizza parte di quelle illustrate ai punti precedenti, ma necessita anche di altre, per esempio i recapiti dei docenti e i programmi dei corsi; 
>- l'ufficio stipendi (quasi sempre diverso dall'ufficio del personale) utilizza le infor-mazioni sulla carriera e quelle sugli incarichi didattici per calcolare le retribuzioni, sulla base delle regole fissate dalla legge e delle eventuali integrazioni locali.
>Se ciascuno di questi soggetti gestisse separatamente le informazioni di proprio interes-se, avremmo molte duplicazioni e, come spesso succede, a lungo andare ci sarebbero molti dati con le varie copie non aggiornate nello stesso modo. Per esempio, potremmo trovare sul sito Web una qualifica diversa da quella corretta, riportata nell'archivio dell'ufficio del personale.

>[!definition]
>DBMS
>> Un sistema di gestione di basi di dati è un sistema software in grado di gestire collezioni di dati che siano
>>  - **grandi** 
>>  - **condivise** 
>>  - **persistenti**
>>  - **affidabilità**
>>  - **privatezza**
>>  - **efficiente**
>>  - **efficace**

+ **Grandi:** possono avere dimensioni enormi (molto maggiori della memoria centrale disponibile)
	+ petabyte
	+ contengono miliardi di **record**
	+ prevedere una gestione di dati in memoria **secondaria**
	+ architetture molto **articolate e sofisticate**
>[!defnition]
>**Mole**: basi di dati hanno senso quando vengono applicate a grandi quantità di dati
>> - quantità di dati che supera la capacità della memoria principale
>> - decidere quali dati caricare e mantenere nella memoria principale
>> - eseguire in modo efficiente **operazioni di trasferimento dei dati** da memoria secondaria a memoria primaria
+ **Condivise:** applicazioni e utenti diversi devono poter accedere, secondo opportune modalità, a dati comuni.
	+ riduce la **ridondanza** dei dati
	+ si evitano ripetizioni
	+ si riduce la possibilità di **inconsistenze**
	+ Risolvere i conflitti con le **transazioni**
>[!definition]
>Controllo di concorrenza
>>Garantisce l'accesso condiviso ai dati da parte di molti utenti che operano contemporaneamente.

+ **Persistenti:** hanno un tempo di vita che non è limitato a quello delle singole esecuzioni dei programmi che le utilizzano.
	+ i dati gestiti in **memoria centrale** hanno una vita che inizia e termina con l'esecuzione del programma (dati non persistenti)
>[!definition]
>**Persistenza**
>> - risiede stabilmente nella **memoria secondaria**
>> - **esiste indipendetemente** dai programmi che interagiscono con essa
+ **Affidabilità:** capacità del sistema di conservare intatto il contenuto della base di dati
	+ funzionalità di salvataggio e ripristino
	+ gestiscono **versioni replicate** dei dati collocate su 
		+ dispositivi fisici diversi
		+ server disposti a distanza
+ **Privatezza**: ciascun utente, opportunamente riconosciuto, viene abilitato a svolgere solo determinate azioni sui dati, attraverso meccanismi di **autorizzazione**
+ **Efficienti**: sono capaci di svolgere le operazioni utilizzando un insieme di risorse (tempo e spazio) accettabile per gli utenti
	+ dipende da
		+ l'implementazione del DBMS
		+ la bontà della realizzazione della base di dati da parte di noi coglioni
	+ garantiscono efficienza solo se il sistema informatico su cui sono installati sia adeguatamente dimensionato
+ **Efficaci**: capaci di rendere produttive le attività dei loro utenti.

>[!tip]
>I DBMS sono stati concepiti e realizzati per estendere le funzioni del **file system**, fornendo la possibilità di accesso condiviso agli stessi da parte di più utenti e applicazioni e garantendo molti servizi in maniera integrata.

>[!question] Perché non usare il file system ?
>**Esempio:** applicazione in ambito bancario
>+ ridondanza e inconsistenza dei dati: questione fondamentale che vogliono risolvere i database
>	+ avere uno stesso dato ripetuto più volte crea un problema di consistenza
>	+ ridondanza quando è **inconsapevole** è un **problema**
>+ difficoltà di accesso ai dati
>+ disomogeneità dei dati
>	+ formati delle date
>		+ indirizzi
>		+ ecc...
>	+ problemi di integrità dei dati
>		+ inserire un dipendente uniud in un dipartimento che non esiste
>	+ (non) atomicità delle operazioni di accesso ai dati
>		+ **rollback**: tutte le operazioni falliscono e quindi si riporta il database a com'era
>		+ prima delle operazioni effettuate
>	+ anomalie causate da accessi concorrenti ai dati
>	+ problemi di sicurezza/protezione dei dati
# Modelli dei dati

>[!definition]
>Modello dei dati
>>Insieme di concetti utilizzati per organizzare i dati di interesse e descriverne la struttura in modo che essa risulti comprensibile a un elaboratore.

In ordine cronologico:
+ reticolare e gerarchico
+ relazionale ed entità/relazioni
+ orientato agli oggetti
+ basati sulla (programmazione) logica
+ ibridi relazionali e orientati agli oggetti
+ modelli basati su XML

### Esempio

CLIENTI: CF, CITTA, CC POSSEDUTI
CC: NUMERO DI CONTO, AMMONTARE, POSSESSORE

## Meccanismi di strutturazione
Analoghi ai costruttori di tipo nei linguaggi di programmazione, che permettono di definire nuovi tipi sulla base di tipi predefiniti e costruttori di tipo.
>[!example]
>C permette di costruire tipi per mezzo dei costruttori:
> - `struct`
> - `union`
> - `enum`
> - `*`(pointer)

## Modello relazionale
+ Il più diffuso
+ definire tipi per mezzo del costruttore **relazione**
+ organizzare i dati in insiemi di **record** a struttura fissa
+ relazione rappresentata attraverso una tabella:
	+ **righe**: specifici record
	+ **colonne**: campi dei record

Lo schema di una relazione è costituito dalla sua **intestazione**:
+ Nome della relazione
+ nomi dei suoi attributi

L'**istanza di una relazione** è costituita dall'insieme (variante nel tempo) delle sue righe.

## Livelli di astrazione nei DBMS

+ **Schema logico**: una descrizione dell'intera base di dati per mezzo del modello logico adottato dal DBMS (relazionale o oggetti)
+ **Schema interno**: rappresentazione dello schema logico per mezzo di **strutture fisiche** di memorizzazione.
>[!example]
>Una relazione può essere realizzata fisicamente per mezzo di
>- un file sequenziale 
>- un file hash
>- un file sequenziale con uno o più indici

+ **Schema esterno**: la descrizione di una porzione della base di dati di interesse per mezzo del modello logico.
	+ può prevedere organizzazioni dei dati diverse rispetto a quelle utilizzate nello schema logico che riflettono il punto di vista di un particolare utente o insieme di utenti
	+ associare a uno schema logico vari schemi esterni

## Indipendenza dei dati

>[!tip]
>L'architettura a livelli garantisce l'**indipendenza dei dati**, la principale proprietà dei DBMS

Permette a utenti e programmi applicativi che utilizzano basi di dati di interagire a un elevato livello di astrazione.

+ **Indipendenza fisica**:
	+ consente di interagire con il DBMS in modo indipendente dalla struttura fisica dei dati
	+ possibile modificare le strutture fisiche
	+ senza influire sulle descrizioni dei dati ad alto livello e su programmi che utilizzano i dati
+ **Indipendenza logica**: 
	+ consente di interagire con il livello esterno in modo indipendente dal livello logico
>[!example]
>È possibile **aggiungere** uno schema esterno in base alle esigenze di un nuovo utente oppure **modificarne** uno senza modificare lo schema logico e l'organizzazione fisica dei dati.

>[!warning]
>Gli accessi alla base di dati avvengono solo attraverso il **livello esterno** (che può coincidere con quello logico).
>Il DBMS traduce le operazioni in termini dei **livelli sottostanti**.

### ACID

>[!definition]
>**Modello ACID**: proprietà chiave di una **transazione**
>> - Atomicità
>> - Coerenza
>> - Isolamento
>> - Durabilità

#### Atomicità
+ Operazione che viene completata tutta o niente.
+ Se una transazione non riesce o si interrompe a metà, tutte le modifiche devono essere annullate (**rollback**)

#### Coerenza
+ Ogni transazione mantiene il database consistente
+ Alla fine della transazione i dati devono rispettare tutte le **regole di integrità** definite nel database

#### Isolamento
+ Transazioni devono essere **isolate** l'una dall'altra
+ eseguita come se fosse l'unica in esecuzione
+ le modifiche effettuate da una non sono visibili finché non è stata completata (commit)

>[!definition]
>Livelli di isolamento:
>> - **Read Uncommitted:** una transazione può vedere i dati di altre transazioni non ancora confermate
>> - **Read Committed:** può vedere solo i dati che sono stati confermati
>> - **Repeatable Read:** transazione vedrà gli stessi dati ogni volta che li legge
>> - **Serializable:** garantisce massimo isolamento, evita qualsiasi interferenza

#### Durabilità
* Le modifiche devono essere **permanenti** e non vanno mai perse
* dati scritti in modo sicuro sul disco
## Caratteristiche generali:

+ facilità d'uso (**indipendenza** dei dati)
+ ottimizzare il numero di trasferimenti da memoria secondaria a memoria principale
	+ **indici**
+ **efficacia** (convenienza)
